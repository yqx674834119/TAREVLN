## 集成范围与验证

- 下载并缓存 NVIDIA Office 的 905 个场景依赖；生成 3,785 个静态碰撞网格，保留原始门的开闭几何，补充室内灯光。
- 编译 SysNav 固定版本 `478727e5a559be22822d5d093b57431449336287` 中的五个仿真相关 ROS 包。使用其原生 TARE 和运动链；语义部分为本项目的候选式 VLM 适配器，未运行完整 SysNav Room / YOLO / SAM 流程。
- DeepSeek 官方视觉 API 使用 `deepseek-flash`。密钥只保存在服务器私有 0600 文件中。记录输入图像、候选、模型答案、调用延迟和网络重试，便于复核。
- 导航进程通过独立文件系统和进程命名空间隔离，不能读取场景或 oracle；ROS 使用 localhost、domain 93。
- 29 项 Python 检查在远端通过；覆盖非法候选、视角对应、过期/重复确认、独立复核以及 API 失败处理。原生候选选择队列另经 10,000 次实际方法回归，修复了缩小队列后仍按原长度采样导致的越界。编译、回放、仿真完成分开记录。
- GPU 兼容库仅对项目进程动态链接，没有重启机器或替换系统驱动。没有连接或驱动实体机器人。

## 当前边界与下一步

1. **会议室任务仍未通过。** 需要针对门槛、门洞净宽、点云覆盖与 TARE 碰撞/连通性逐项检查；不能让 VLM 凭图像添加穿墙路径。近距离观察候选可改善接近与确认，不能替代门洞可通行验证。
2. **Go2 步态质量未通过。** 后续复查更正：上述运行的小腿/大腿事件冲量全为零，旧记录没有保存接触间距，不能认定腿部擦地，也不足以证明无几何接触。新的独立平地测试保存原始接触点、间距和冲量，已确认低速速度跟踪不足及前进时 8 次头部受力接触。任务完成不代表可迁移到实机，详见 [上机准备迭代记录](readiness/iteration-01.md)。
3. **定位与传感器仍理想化。** 使用模拟器位姿、虚拟多线雷达和四向 RGB-D；需要逐步换为匹配机器狗配置的传感器、噪声、遮挡、SLAM 和标定链路。
4. **像素与物体的绑定仍不精确。** 最终运行第一个锚点在桌面高度约 0.452 米；第二个标点偏到桌子后方的墙面，高度约 0.650 米，仍通过了几何高度与距离门限。`grounding.valid` 只说明像素/深度/距离/高度检查通过，不证明其语义对象归属。任务最终位置和设施组合确实通过独立区域检查及画面复核，但不能据此宣称精确三维对象定位。下一步应接入三维分割/平面法线及跨视角关联，减少这种错误。
5. **当前只证明一个单场景组合语义任务可自主完成。** 后续固定版本后，按多个起点、不同家具布局和相似干扰区域评估成功率、路径效率、误停率、VLM 成本与重复探索；再做无 VLM、无连接/空间记忆、无独立复核、无近距离候选的受控对照。
