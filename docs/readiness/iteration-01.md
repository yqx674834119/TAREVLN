# 上机准备：第一轮诊断与修复

日期：2026-09-27。仿真服务器 5090；生产 TARE_WheelTECH 未修改。此页记录开发证据，不是上机通过报告。

## 运动：独立基线与上游对照

`sim/diagnose_go2.py` 创建独立平地，依次测试静止、0.3 m/s 前进、0.2 m/s 后退和左右侧移、0.5 rad/s 原地转向、停止。200 Hz 力矩控制、50 Hz 策略，保留每个阶段前一秒的过渡数据，但稳定段误差统计剔除该秒。

| 稳定段主轴 RMS 误差 | 项目控制器基线 | 官方 Isaac Lab 环境，同一权重 |
|---|---:|---:|
| 前进，m/s | 0.231 | 0.061 |
| 后退，m/s | 0.178 | 0.193 |
| 左侧移，m/s | 0.197 | 0.198 |
| 右侧移，m/s | 0.047 | 0.038 |
| 原地转向，rad/s | 0.462 | 0.499 |

上游对照使用 `IsaacLab v2.3.0`，提交 `3c6e67bb5c7ada942a6d1884ab69338f57596f77`，标准 Flat PLAY 配置，固定出生位姿，去除附加基座质量，保留官方动作/观测管理器、物理和接触传感器。关节顺序、默认角度均与项目代码一致。对照支持“低速控制缺陷不只来自项目封装”，不证明全部动力学参数相同。

远端证据：

- `data/readiness/gait/baseline-yaw0-r2/`：项目基线；`states.jsonl`、完整 `contacts.jsonl` 和旧诊断报告。
- `data/readiness/gait/isaaclab-yaw0/`：项目封装中对齐部分上游物理参数的对照，改进有限。实例化碰撞体的材质未全部覆盖，因此不是完整复现。
- `data/readiness/gait/upstream-lab-yaw0-r1/`：直接由官方 ManagerBasedRLEnv 执行，包含官方接触力、配置和身体名称。

旧 Office 日志按“出现非脚部事件”直接判失败，忽略 PhysX 可以上报分离状态、零冲量的邻近事件。平地原始记录证实大量小腿事件间距为正且冲量为零。**修复判据并保留所有事件**：受力冲量大于 `1e-5 N s` 或间距小于等于 `0.5 mm` 才计入物理接触。基线仍有 8 次头部受力接触，发生在前进阶段，不能靠修正统计把它标成通过。旧运行不重写为新判据通过，因为没有保存间距。

`sim/train_go2_control.py` 为独立仿真改进入口，保留官方原权重，只在新目录保存版本。目标是低速前后、侧移、原地转向和停止，增加高度与非脚部接触约束。新权重必须重新通过固定动作、多个朝向和门槛测试才可替换导航默认配置；训练回报上涨不能替代这些验收。该权重不作为真实机器狗低层控制器部署。

## RGB-D：拒绝墙面误点

`office_grounding.py` 在已有深度、距离和高度检查上增加四个像素尺度的表面法向及平面残差验证，至少三个尺度必须符合近水平表面。原始图像和深度直接驱动该检查，不读取 USD、oracle 或对象真值。

固定 8 个历史 RGB-D 小块中，两处桌面保留，六处墙面/地面误点被拒绝，包含上一轮被错误接受的 `front [320,240]`。数据及源文件 SHA-256 保存在 `tests/fixtures/office_anchor_patches.json`，提取脚本为 `scripts/extract_anchor_regression.py`。这些是助手视觉复核的开发回归样本，不能称为独立人工标注测试集。水平椅面仍可能通过几何判据，对象身份与跨视角关联尚未完成。

修改后闭环 `office-lounge-006-surface` 完成：71.215 秒仿真、168.474 秒实际运行、11.840 米、18 次 VLM 调用。三个有效锚点高度为 0.4516、0.4520、0.4521 米，均在同一小桌的独立资产边界内；姿态重复的第二次观察没有提前触发停止。最终在预定区域内静止 1.1 秒。完整接触点记录下，本轮非脚部物理接触为零，原始零冲量邻近事件仍保留。此次是单次开发验证，不是冻结配置后的成功率。

## 会议区域：全场几何只供评测审查

新增 `sim/audit_office_routes.py` 将静态网格在高度 0.08–0.8 米范围投影到 5 cm 网格，使用半径 0.35 米并加栅格容差的占据膨胀。三处会议目标区域都有离线可行路线，长度约 15.0、14.8、11.1 米。通路经过 `(x≈-5,y≈28.5)` 的开放门洞，因此不能把失败归因为所有会议室都关闭。

该圆形包络和高度切片是评测侧几何可行性审查，不是完整机器人姿态碰撞证明，也不是在线规划结果。占据图和路径保存在 `data/readiness/office-geometry-r2/`，不挂载进策略进程。下一步检查在线点云覆盖、候选筛选和实际转向/穿门。12 次任务组合与运动误差阈值已经分别预定义在 `config/readiness/office-suite.json` 和 `gait-gates.json`。

## 运动出口：仅实现契约，未连接硬件

`vln_core.motion_guard` 默认禁止运动；显式启用还要求命令、定位、扫描、机器人连接、操作者使能信号均新鲜。命令去重、限速、加速度限制、急停锁存、时钟回退、看门狗超时与失联均有故障注入检查。停止绕过加速度缓变，恢复输入不会自行重新启用。时间来自接收方单调时钟，不能用消息自报时间延长有效期。

该模块没有网络或机器狗驱动，单元测试不等于厂商 API、设备侧看门狗或无运动台架验证。具体型号/计算平台/传感器信息仍待确认；不会沿用 SysNav 原节点启动即关闭避障的行为。

## 环境补齐

既有 Isaac Python 环境的 PyTorch 不包含 `sm_120`，GPU 分配直接报 `no kernel image`；此前 CPU 推理通过不能证明 GPU 训练可用。CUDA 12.8 版 PyTorch 安装到 `~/VLN/envs/torch-cu128`，由 `scripts/with_training_env.sh` 仅对目标进程加入模块搜索路径，仍经过原 GPU 兼容库脚本。不替换系统驱动，不重启。

已验证该独立环境报告 `2.7.0+cu128`、包含 `sm_120`，并在 RTX 5090 上完成矩阵乘法、反向传播和有限梯度检查。训练与导航任务的 GPU 使用顺序执行。项目核心测试目前远端 45 项通过，本地 44 项通过、1 项因无 NumPy 跳过；这些不代替运动或硬件验收。
